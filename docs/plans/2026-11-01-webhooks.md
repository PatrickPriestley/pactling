# Phase 5: webhooks

Branch `feat/webhooks`, started 2026-11-01. Goal: the Ruby broker's webhook resources, event
triggering, delivery with retries and execution logs, so `pact-broker create-webhook`,
`test-webhook` and a CI receiver work unchanged against pactling.

## Evidence

Captured from Ruby broker 2.121.2 with `scripts/capture-ruby-fixtures.sh` (new phase 5
section; `e2e/receiver.js` records what the broker sends) into
`tests/fixtures/ruby-broker/2.121.2/phase5/` and `tests/fixtures/cli/phase5/`, and read in
the gem's source (`lib/pact_broker/webhooks/*`, `api/contracts/webhook_contract.rb`,
`config/runtime_configuration.rb`). Verified facts:

- Defaults: `webhook_scheme_whitelist ["https"]`, `webhook_http_method_whitelist ["POST"]`,
  `webhook_http_code_success [200..206]`, `webhook_host_whitelist []`,
  `webhook_retry_schedule [10, 60, 120, 300, 600, 1200]` seconds; the response body is
  logged only when a host whitelist is configured. The probe compose passes
  `PACT_BROKER_WEBHOOK_SCHEME_WHITELIST=http` for the capture.
- Events: contract_published, contract_content_changed (default when `events` is omitted),
  contract_requiring_verification_published (one trigger per provider version that is the
  main-branch head or currently deployed/released, with `providerVersionDescriptions`
  "latest from main branch" / "deployed in test"), provider_verification_published,
  provider_verification_succeeded, provider_verification_failed.
- Validation messages and shapes: `request` "is missing" / "must be filled";
  `request.method` "must be POST. See /doc/webhooks#whitelist for more information.";
  `request.url` "scheme must be https. See ...", "is not a valid URL eg. http://example.org",
  "cannot have a template parameter in the host"; `events` "name must be one of: ... (at
  index 0)", "size cannot be less than 1"; `consumer.name` "does not match an existing
  pacticipant"; `consumer.label` "name and label cannot be provided at the same time";
  `uuid` "The UUID can only contain the characters A-Z, a-z, 0-9, _ and -, and must be 16
  or more characters." Unknown webhook: plain-JSON 404.
- The CLI posts `create-webhook` to `/webhooks/provider/{p}/consumer/{c}` (or `/webhooks`
  without scope), `create-or-update-webhook` PUTs `/webhooks/{uuid}` and `test-webhook`
  POSTs `/webhooks/{uuid}/execute` and prints the `logs` field.
- Generated uuids are 22 url-safe base64 characters. Description defaults to
  "POST <host>"; list titles are "A webhook for the pact between C and P" / "all pacts with
  provider P" / "all pacts with consumer C" / "all pacts". Headers named like authorization
  or token and the password are shown as "**********"; header names are lower-cased.
- The request the broker sends: `user-agent: Pact Broker v2.121.2`, `accept: */*` unless a
  header overrides it, basic auth from username/password, `content-type:
  application/x-www-form-urlencoded` when no content-type header is set, a JSON object
  body serialised compactly, the string `null` when there is no body. Every
  `${pactbroker.*}` parameter expands as `PactAndVerificationParameters#to_hash`; the test
  execution uses event name `test` and the latest pact and verification. URL parameters
  are percent-encoded, body parameters are not.
- Delivery: a triggered webhook per (webhook, event, expanded context) in the order
  contract_published, contract_requiring_verification_published, contract_content_changed;
  the i-th is scheduled 5 + 3i seconds later; statuses not_run, retrying (attemptsMade n,
  attemptsRemaining 7 - n), success, failure after 7 attempts; executions carry a log text
  with `[time] LEVEL: line` lines; deleting the webhook keeps its triggered webhooks with a
  null name and no `pb:webhook` link. The publish response lists each trigger as a debug
  notice "  Webhook X triggered for event Y.\n    View logs at <url>".
- `/pacts/provider/{p}/consumer/{c}/webhooks/status` summarises the latest triggered
  webhook per (webhook, event): `successful`, `failed`, plus `notRun` / `retrying` only
  when non-zero.

## Decisions

- Delivery runs inside the server as a tokio task polling `triggered_webhooks` every
  second for rows due (`next_attempt_at`), so a restart loses nothing. Rejected: an
  in-memory queue (lost on restart) and a separate worker binary (not drop-in).
- The user agent is `Pact Broker v2.121.2`-compatible: `Pactling/<version>`; listed as a
  deliberate difference in the README. Rejected: impersonating the Ruby version string.
- Configuration uses the Ruby variable names (`PACT_BROKER_WEBHOOK_SCHEME_WHITELIST`,
  `..._HOST_WHITELIST`, `..._HTTP_METHOD_WHITELIST`, `..._HTTP_CODE_SUCCESS`,
  `..._RETRY_SCHEDULE`), space-separated lists, Ruby's defaults.
- Labels are stored and rendered but never match anything (pactling has no labels yet);
  `currentlyDeployedProviderVersionNumber` expands to "" as in the capture (feature off).
